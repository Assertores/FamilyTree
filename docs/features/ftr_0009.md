# Building an own Application on the Library
<!-- State: Proposed (not part of a work package yet), Planned (part of a work package), In Progress (one of its work packages is being implemented), Implemented (all its work packages are Done), Done (every scenario has a passing end-to-end test), Rejected (dropped without a successor; a replaced FTR keeps its state and gets `Replaced by` instead). -->
## User Story
<!-- Who wants what, and why. Use the form: As a <user group>, I want <goal>, so that <benefit>. The user group should match one from the vision's Target Users. -->
As an integrator, I want to build my own Application on the Library, read the data in my own way and show the Media in my own way, e.g. with my own audio player, so that I can present the family in my own way and adapt the Library to my system.

## Requirements

| Requirement | Constraint |
| ---: | :--- |

| [REQ 0043](../requirements/req_0043.md) | Every public function and type is documented in its header file. |
| [REQ 0044](../requirements/req_0044.md) | The Application can provide a Trace, but does not have to. |

## Scenarios
<!-- Concrete examples of the feature's behavior: the normal case first, then edge cases and errors. Every step must be observable from the outside. -->
### An own audio player
- **Given** an Application with its own audio player, and a Person whose Recording lies in their Person Folder
- **When** the Application asks the Library for the Recording of the Person
- **Then** it receives the path of the Recording within the Person Folder, and nothing is played until the Application plays it

### Defaults for the rest
- **Given** an Application that reads files itself, and leaves listing folders and checking files to the Default Platform
- **When** it opens a Data Folder
- **Then** the Data Folder opens, with every file read by the Application

### Two Contexts side by side
- **Given** two Contexts, each opened on a different Data Folder
- **When** the Application searches for a Person in one of them
- **Then** the results of searches in the other Context stay the same

### No Trace
- **Given** an Application that provides no Trace
- **When** it opens a Data Folder with a malformed Person File
- **Then** the Library opens the rest of the Data Folder without crashing

### Releasing a Context
- **Given** a Context from which the Application has requested Persons, Relations and a Family Tree
- **When** the Application frees the Context
- **Then** a memory checker reports no memory left allocated by the Library
