# Correcting a Person
<!-- State: Proposed (not part of a work package yet), Planned (part of a work package), In Progress (one of its work packages is being implemented), Implemented (all its work packages are Done), Done (every scenario has a passing end-to-end test), Rejected (dropped without a successor; a replaced FTR keeps its state and gets `Replaced by` instead). -->
## User Story
<!-- Who wants what, and why. Use the form: As a <user group>, I want <goal>, so that <benefit>. The user group should match one from the vision's Target Users. -->
As a data collector, I want to open a Person I recorded earlier, change it and save it again, so that I can add what I learn later and correct my mistakes.

## Requirements
<!-- The REQs that constrain how this feature may be built, and how each one affects it. -->
| Requirement | Constraint |
| ---: | :--- |
| [REQ 0033](../requirements/req_0033.md) | Only Person Files with a supported Format Version are opened, and saving them again loses none of their content. |
| [REQ 0032](../requirements/req_0032.md) | The saved Person File has the current Format Version. |
| [REQ 0034](../requirements/req_0034.md) | The user chooses where the Person File is saved. |
| [REQ 0005](../requirements/req_0005.md) | Keys the Library does not know are part of the content, and are kept. |
| [REQ 0031](../requirements/req_0031.md) | The changes are entered in the same form as a new Person. |
| [REQ 0046](../requirements/req_0046.md) | Every label and button is in German. |

## Scenarios
<!-- Concrete examples of the feature's behavior: the normal case first, then edge cases and errors. Every step must be observable from the outside. -->
### Adding a date of death
- **Given** a Person File without a date of death
- **When** the user opens it in the Data Entry Tool, enters a date of death and saves it
- **Then** the Person File contains the date of death, and every other Detail is unchanged

### Keeping unknown keys
- **Given** a Person File that contains the key "death", which the Library does not know
- **When** the user opens it in the Data Entry Tool and saves it again
- **Then** the saved Person File still contains the key "death" with its value

### A Person File of an unsupported Format Version
- **Given** a Person File with a Format Version the Data Entry Tool does not support
- **When** the user tries to open it
- **Then** the Data Entry Tool does not open it
