# Entering a new Person
<!-- State: Proposed (not part of a work package yet), Planned (part of a work package), In Progress (one of its work packages is being implemented), Implemented (all its work packages are Done), Done (every scenario has a passing end-to-end test), Rejected (dropped without a successor; a replaced FTR keeps its state and gets `Replaced by` instead). -->
## User Story
<!-- Who wants what, and why. Use the form: As a <user group>, I want <goal>, so that <benefit>. The user group should match one from the vision's Target Users. -->
As a data collector, I want to fill in what I know about a Person in a form in German, and save it, so that I can record my family without writing JSON by hand.

## Requirements
<!-- The REQs that constrain how this feature may be built, and how each one affects it. -->
| Requirement | Constraint |
| ---: | :--- |
| [REQ 0031](../requirements/req_0031.md) | The form offers the Person Id, every Detail and the references to the Media. |
| [REQ 0032](../requirements/req_0032.md) | The saved Person File has the current Format Version, and the Library reads all the entered data. |
| [REQ 0034](../requirements/req_0034.md) | The user chooses where the Person File is saved. |
| [REQ 0046](../requirements/req_0046.md) | Every label and button is in German. |
| [REQ 0002](../requirements/req_0002.md) | The Person Id must not be used by another Person File of the same Data Folder. |
| [REQ 0003](../requirements/req_0003.md) | The saved file uses the keys and types the Library reads. |
| [REQ 0010](../requirements/req_0010.md) | The saved file is encoded in UTF-8. |
| [REQ 0001](../requirements/req_0001.md) | The Person File is saved as "data.json" in a Person Folder, so that the Library reads it. |
| [REQ 0009](../requirements/req_0009.md) | The Browsing Application shows the entered Details exactly as entered, e.g. "um 1850". |
| [REQ 0028](../requirements/req_0028.md) | The Browsing Application shows every entered Detail, and the others as unknown. |

## Scenarios
<!-- Concrete examples of the feature's behavior: the normal case first, then edge cases and errors. Every step must be observable from the outside. -->
### Recording a Person
- **Given** the Data Entry Tool with an empty form
- **When** the user enters the Person Id 19, the first names "Anna" and "Maria", the last name "Huber" and the date of birth "um 1850", and saves the Person File as "data.json" in a new Person Folder of a Data Folder
- **Then** the Browsing Application, opened on that Data Folder, shows Anna Maria Huber with exactly these Details

### Umlauts
- **Given** the Data Entry Tool with an empty form
- **When** the user enters the place of birth "Würzburg" and saves the Person File in a Data Folder
- **Then** the Browsing Application, opened on that Data Folder, shows the place of birth "Würzburg"

### Choosing where to save
- **Given** a filled in form
- **When** the user saves it and chooses a folder
- **Then** the Person File is written into that folder

### German user interface
- **Given** a computer whose user only reads German
- **When** the user starts the Data Entry Tool
- **Then** every label and button is in German
