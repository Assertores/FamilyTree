# Trace
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
Following the flow of C code is hard, and a recorded trace may be the only way to find the cause of a problem a user reports.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
The Library SHALL report its steps and the failures it runs into to the Trace the Application provides. If the Application provides no Trace, the Library SHALL work as if it had been given a Trace that discards every report.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
A Trace shows what led to a problem without a debugger on the user's computer, while Applications that do not need it are not burdened by it. Because there is always a Trace to report to, every requirement that asks for a report to the Trace also holds when the Application provides none.
