# Text that is not UTF-8
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
A data file edited with a program that does not save UTF-8 can contain single values in another encoding, e.g. an umlaut in Latin-1. The other requirements do not decide which part of the data the Library skips then.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
When a value in a Person File is not valid UTF-8, the Library SHALL skip only that value. When a row of the Relations File is not valid UTF-8, the Library SHALL skip only that row. The Library SHALL report every skipped value and row to the Trace.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
One wrongly encoded place name must not cost the whole Person or all Relations; skipping the smallest readable part keeps the most data, and the report tells the data collector what to correct.
