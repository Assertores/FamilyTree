# Unknown keys in a Person File
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
Person Files are written by hand or by tools, and can contain keys the Library does not know, e.g. misspelled keys or keys added by a later Format Version.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
In a Person File it reads, the Library SHALL ignore keys that it does not know, SHALL report each of them to the Trace, and SHALL read the rest of the Person File.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
One unknown key must not make a whole Person unreadable. Reporting it lets the data collector find a misspelled key, which would otherwise silently lose the Detail it holds. The report to the Trace is a concrete case of reporting every step, named here so that it can be tested.
