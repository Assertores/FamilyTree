# Duplicate Person Ids
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
[REQ 0002](req_0002.md) forbids two Person Files of the same Data Folder with the same Person Id, but no requirement says what the Library does when the data breaks that rule. The vision assumes that the Library reports duplicate ids when loading ([OQ 0008](../open_questions.md)). The Library finds a Person by the Person Id, so it can keep only one Person per Person Id.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
If several Person Files of a Data Folder have the same Person Id, the Library SHALL read only the Person File whose Person Folder name comes first in the byte order of its UTF-8 text, SHALL skip the other Person Files, and SHALL report each skipped Person File to the Trace.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
The order of the Person Folder names decides which Person File is read, not the order in which the operating system lists the folders, which differs between operating systems; so the same Data Folder gives the same Context everywhere. Skipping the other Person Files and reporting them follows how the Library treats every other problem in the data, while refusing the whole Data Folder would keep a family from being explored because of a single mistyped Person Id. Keeping one of the Person Files loses less than skipping all of them.
