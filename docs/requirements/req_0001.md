# Reading Person Files
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
The data collector keeps every Person in a Person Folder of its own, next to the Person's Media. The existing data names the Person File in every Person Folder `data.json`. The format of the Person File may have to change in the future, after data has been collected; data written before the Format Version existed is not supported.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
The Library SHALL read the Person File named "data.json" from every Person Folder of a Data Folder, if the Library supports its Format Version. The Library SHALL skip every other Person File, and SHALL report it to the Trace.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
One folder per Person keeps a Person's Person File and Media together, so that they can be found, copied and read by a person without any program. Keeping the existing file name keeps the existing data readable. Reading a Person File in a format the Library does not understand would silently produce wrong Details. The Format Version makes it possible to support older formats later, while files without one are excluded on purpose. The report to the Trace is a concrete case of reporting every step, named here so that it can be tested.

### Several Person Files with the same Person Id
Andreas Edmeier
> Settled while implementing the Library Skeleton, 2026-11-16: [REQ 0053](req_0053.md) limits "every Person Folder". Of several Person Files with the same Person Id, the Library reads only the one whose Person Folder name comes first in byte order, and skips the others with a report to the Trace.
