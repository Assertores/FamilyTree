# Reading the Relations File
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
The data collector writes the Relations between Persons as rows of a CSV file. The existing data names it `relations.csv` and starts it with a header line. Unlike the Person File, the Relations File carried no Format Version so far, so a change of its format could not be detected.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
The Library SHALL read the Relations File named "relations.csv" from a Data Folder, if the Library supports its Format Version. The Library SHALL skip any other Relations File, and SHALL report it to the Trace. The first line of the Relations File SHALL contain the text "Version" and the Format Version, in this order. The Library SHALL ignore the second line.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
A CSV file can be written and read with any text editor or spreadsheet program, today and in the future. Keeping the existing file name keeps the existing data easy to move over. The Format Version in the first line lets the format of the Relations File change in the future, like that of the Person File, and a Relations File in a format the Library does not understand is skipped instead of producing wrong Relations; the word "Version" in front of it tells a reader what the UUID means. The second line keeps a header that tells a reader what each column means. The report to the Trace is a concrete case of reporting every step, named here so that it can be tested.
