# Values of the Relation Type
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
The Relations File writes the Relation Type as text.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
The Library SHALL read the Relation Type "Unrestricted", "StrictlyLower" and "StrictlyHigher" as Unrestricted, Strictly Lower and Strictly Higher. The Library SHALL read any other value, and an empty value, as Unrestricted, and SHALL report a warning to the Trace.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
These values are already used in existing data. Unrestricted is the only Relation Type that does not move Persons between Generations, so it is the safest reading of a value the Library does not understand, while the warning lets the data collector find and correct it.
