# UTF-8 text
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
Names and places of a family can contain characters of any language. Data files edited by hand can end up in another encoding, e.g. a text editor that saves an umlaut as a single byte.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
All text in data files SHALL be encoded in UTF-8. The Library SHALL return all text as UTF-8.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
UTF-8 can represent every character and is the most widely used text encoding, so it is the most likely to still be readable in the future. Requiring it of the data files means that text in another encoding is malformed data, which the Library skips and reports, instead of guessing what the bytes were meant to be.
