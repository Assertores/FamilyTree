# Path of the Recording
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
A Recording keeps the voice and the stories of a Person, which is more personal than any written Detail. Applications play it in different ways, e.g. the Browsing Application in its story player.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
The Library SHALL provide the path of the Recording of a given Person. On Windows and Linux, the Library SHALL offer a default way to play a Recording with the program the operating system uses for it.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
Providing the path lets every Application decide how to play the Recording, without the Library calling back into the Application. Applications that do not care use the default way.
