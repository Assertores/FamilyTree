# Optional content of a Person File
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
The data collector rarely knows every Detail of a Person. The existing data and the template given to the data collector use fixed keys for the Details and the Media.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
A Person File MAY contain the keys "Title", "TitleOfNobility", "Gender", "DateOfBirth", "PlaceOfBirth", "DateOfDeath", "PlaceOfDeath", "Audio" and "Remarks" with a string value each; the keys "FirstNames", "LastNames", "Profession" and "Images" with an array of strings each; and the key "PlaceOfResidence" with an array of objects, each of which MAY contain the keys "Name", "StartDate" and "EndDate" with a string value each. In a Person File it reads, the Library SHALL read each of these keys that is present. The Library SHALL skip a key whose value has another type than stated here, and SHALL report it to the Trace.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
Missing information must not prevent a Person from being recorded. The keys are already used in existing data, so they cannot change without breaking it.
