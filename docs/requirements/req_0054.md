# Byte order mark
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
Some programs on Windows write the three bytes of a UTF-8 byte order mark at the start of a UTF-8 file, e.g. Excel when it saves a file as "CSV UTF-8". The data collector writes the Relations File by hand, possibly with such a program. A byte order mark is valid UTF-8 ([REQ 0010](req_0010.md)), but without a rule for it a Relations File would have no version line and be skipped ([REQ 0006](req_0006.md)), and a Person File would be malformed JSON and be skipped ([REQ 0013](req_0013.md)).

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
The Library SHALL ignore a UTF-8 byte order mark at the start of a data file.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
A byte order mark is how common programs write UTF-8, not a mistake in the data, so the data collector cannot be expected to avoid it, and a warning about it would only distract. UTF-8 has no byte order, so the mark carries no information the Library needs. A file that starts with the byte order mark of another encoding, e.g. UTF-16, is not UTF-8, and is skipped as before.
