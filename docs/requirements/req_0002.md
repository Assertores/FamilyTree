# Mandatory content of a Person File
## Context
<!-- The situation that makes this requirement necessary, e.g. a user need, a law or standard, or a constraint from another system. -->
Every existing Person File carries its Format Version under the key "Version" and its Person Id under the key "Id". Without them, a Person File cannot be read safely or referred to by Relations.

## Requirement Statement
<!-- A bland statement of the requirement using the [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) standardized vocabulary. The ruling SHALL be stated in an assertive voice. It SHALL NOT contain definitions or links, not even to other REQs; terms are defined in the glossary. -->
A Person File SHALL be a JSON document that contains the key "Version" with a UUID as its string value and the key "Id" with an integer value that no other Person File of the same Data Folder has.

## Justification
<!-- A sound reasoning why this requirement exists and not another one. Any revision of the REQ MUST take the justification into serious consideration. -->
The Format Version decides how the rest of the file is read. A UUID lets formats develop separately from each other and be merged again later, without conflicting version numbers, and the Person Id is the only way the Relations File refers to a Person.
