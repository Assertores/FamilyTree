# install-qt-action
## Choice
<!-- Exactly what was chosen. -->
| Name | Version | Source | License |
| ---: | :--- | :--- | :--- |
| install-qt-action | 4.5.0 | https://github.com/jurplel/install-qt-action | MIT |
| aqtinstall, on Windows | commit `076e1659807d0b362a3ed684d54c2e9c775eb9c7` of the branch master | https://github.com/miurahr/aqtinstall | MIT |

## Description
<!-- What the dependency is, what it does, and what this project uses it for. -->
A GitHub Action that downloads and installs a given version of Qt on a runner, using the Python tool aqtinstall underneath. The continuous integration installs Qt 6.12 with it on the Linux runner, and on the Windows runner in the build for MSVC.

## Alternatives Considered
<!-- What else was evaluated, and what speaks for and against each option. -->
| Name | Pros | Cons |
| ---: | :--- | :--- |
| Qt Online Installer | the official way to install Qt | needs a Qt account, and is made for interactive use |
| Packages of the Linux distribution | no extra tool on Linux | Ubuntu 24.04 has Qt 6.4 only; nothing comparable on Windows |
| aqtinstall called directly with pip | no third-party action | more workflow code for the same tool underneath |

## Justification
<!-- A sound reasoning why this dependency was chosen over the alternatives, and over building it ourselves. Any replacement of the dependency MUST take the justification into serious consideration. -->
One step installs the exact Qt version on both runners, and it is the common way to install Qt on GitHub Actions. Only the continuous integration depends on it; a local build uses any installation of Qt 6.12.

The release 3.3.0 of aqtinstall cannot find Qt 6.11 or newer on Windows, because Qt split its Windows download folder by toolchain. The fix is merged on the branch master of aqtinstall (pull request 1000, "Support Qt 6.11+ for Windows x64"), but not released. The Windows job therefore installs aqtinstall from a pinned commit after the fix, so that Linux and Windows build against the same Qt as [DEP 0001](dep_0001.md). Once aqtinstall 3.4.0 is released, the Windows job returns to a release. The Linux job uses the release that the action chooses.
