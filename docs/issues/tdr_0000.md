# Example Technical Debt Record
## Symptoms
<!-- Observable signs indicating the presence of the technical debt (e.g., frequent bugs, slow performance). -->
There are no examples of TDRs.

## Context
<!-- Detailed background information, including why the debt was incurred (e.g., rushed deadlines, outdated technologies). -->
Up to now there were no technical debt records at all. A decision was made to add TDRs to the repository to keep track of shortcuts taken. This gave rise to the issue of not having any example showing what a TDR looks like.

## Impact
<!-- How the debt affects system performance, scalability, maintainability, etc. -->
No one knows how to write a TDR correctly.

## Cost of Delay
<!-- Consequences of postponing the resolution of the debt. -->
Without an example, TDRs risk being written in inconsistent ways.

## Solution
<!-- Action or strategy taken to resolve the debt. -->
An example is provided to show how TDRs are intended to be used.
